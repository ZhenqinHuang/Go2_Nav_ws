# Go2 直连 Jetson 控制验证记录（2026-07-23）

> 适用环境：Unitree Go2、Jetson Orin NX 16GB、Ubuntu 20.04 ARM64、
> ROS 2 Foxy、`/home/nvidia/Go2_Nav_ws`。
>
> 本记录区分“已验证”和“待验证”。网络、DDS、状态订阅、Sport API 应答和
> 40 cm 闭环前进已经通过实机验证。未经现场人员明确同意，禁止发送任何可能造成
> 站立、姿态变化或移动的指令。

## 1. 当前结论

1. Jetson 可以通过 `eth0` 直连 Go2，Go2 地址为 `192.168.123.161`。
2. Jetson 使用 `192.168.123.99/24` 后可以发现 Go2 的 DDS 话题并接收真实状态。
3. ROS 2 Foxy 自带的 CycloneDDS 0.7 无法解析 Unitree 使用的 0.10 配置格式；
   安装并优先加载 CycloneDDS 0.10.2 后恢复正常。
4. Go2 收到了 Jetson 的 Sport API 请求并返回 `status.code=0`；仅有 API 成功应答
   不能证明已经产生实际位移。
5. 抓取 `/api/sport/request` 后发现，遥控器开启时存在约 50 Hz 的
   `Move(0, 0, 0)` 请求流，持续覆盖 Jetson 的非零速度请求。
6. 关闭遥控器后，`/api/sport/request` 的持续零速度流和
   `/wirelesscontroller` 数据流同步停止，确认冲突来自遥控器链路。
7. `0.10 m/s` 的短时测试只造成机体向前探身，没有进入持续步态。Unitree 官方
   Go2 示例使用 `Move(0.3, 0, 0)`。
8. 最终使用状态闭环程序，以 `0.30 m/s` 前进，在前向位移约 0.38 m 时发送
   StopMove。制动后状态里程计为前向 0.4081 m、横向 0.0239 m、速度归零；现场
   确认机器狗实际前进约 40 cm并正常停稳。

## 2. 网络拓扑

```text

        │

Jetson wlan0 192.168.0.68/24
        │
        └── SSH、GitHub 和互联网；默认路由继续走 wlan0
```

NetworkManager 临时连接名为 `go2-direct`，无网关且
`ipv4.never-default=yes`。它只用于 Go2 控制验证，不应覆盖 Wi-Fi 默认路由。

### 2.2 MID360 到货后的正式拓扑

已经确定 MID360 直连 Jetson `eth0`。由于 Go2 和 MID360 使用不同子网，正式部署
时建议为 Go2 增加一个 USB 3.0 千兆网卡：

```text
MID360 ── Jetson eth0（192.168.1.5/24，雷达专用）
Go2    ── Jetson USB 千兆网卡（192.168.123.99/24，控制专用）
wlan0  ── SSH、互联网和默认路由
```

不要在正式运行时反复把同一个 `eth0` 在 MID360 与 Go2 配置之间切换。

## 6. 控制失败的复现与根因

### 6.1 现象

桥接节点能够把 ROS 2 `geometry_msgs/Twist` 转换为 Unitree Sport API：

- `1008`：Move；
- `1003`：StopMove；
- `1004`：StandUp。

曾分别尝试约 4 cm、40 cm 和 30 cm 的低速前进测试。节点日志显示命令已发布并在
超时后发送 StopMove，但现场观察均为“机器狗没有前进，仍在原地”。

因此下列说法是错误的：

```text
发布成功 = 机器狗已经移动成功
```

必须同时满足“API 应答、状态变化、现场位移观察”才能判定实机控制成功。

### 6.2 请求与应答证据

订阅请求和应答后观察到：

```text
REQUEST  api_id=1008  lease.id=0  priority=0
parameter={"x":0.0,"y":0.0,"z":0.0}
RESPONSE status.code=0
```

该零速度请求在遥控器开启时持续出现，频率约为 50 Hz。Jetson 发出的
StopMove 同样得到 `status.code=0`。这说明：

- DDS 通信正常；
- Go2 的 Sport 服务正常应答；
- 失败点不是“请求没到机器人”，而是“Jetson 的非零请求被持续零速度请求覆盖”。

关闭遥控器后，在 6 秒观察窗内不再出现 `/api/sport/request` 消息，
`/wirelesscontroller` 也停止更新。两条证据共同确认覆盖源来自遥控器链路。

### 6.3 第二阶段：控制生效但没有迈步

关闭遥控器后，使用 `0.10 m/s` 发送短时 Move。现场观察为机体向前探了一下，但
没有迈步。这说明非零请求已经影响运动控制器，同时也说明该速度与持续时间不足以
验证实际行走。

该阶段还暴露了两个测试工具问题：

- ROS 包名实际为小写 `go2_nav2`，使用 `Go2_nav2` 会导致节点没有启动；
- `ros2 topic pub` 的 DDS 发现耗时会占用外层 timeout，计划的 34 帧实际只发出
  17 帧；终止 `ros2 run` 包装进程还可能留下真正的桥接子进程。

因此最终测试不再使用 CLI 帧数估算距离，而改用单一 Python 进程同时完成状态订阅、
Move 发布、距离判定、StopMove 和退出清理。

## 7. Sport lease 的含义与限制

Unitree SDK2 的 `SportClient(bool enableLease=false)` 支持可选租约。官方实现使用：

- `/api/sport_lease/request`
- `/api/sport_lease/response`
- API `101` 申请租约；
- API `102` 续租；
- 默认租期约 1 秒，并在租期内持续续租。

服务端存在有效租约时，不带相同 `lease.id` 的受保护请求会被拒绝。因此租约可以
隔离其他 `lease.id=0` 的 Sport 请求，但也意味着不能未经验证就假设遥控器的
StopMove 或其他控制仍然有效。

当前决定：

- 首次位移验证不自动启用 lease；
- 不自动调用 `SwitchJoystick(false)`；
- 不把遥控器当作租约生效期间已验证的急停装置；
- 是否将 lease 集成到 `go2_cmd_vel_bridge`，要在独立安全测试后再决定。

## 8. 再次执行实机测试的安全门槛

只有现场人员明确说“可以测试”后，才允许进入本节。普通的状态询问、接线确认或
“继续排查”都不等于运动授权。

测试前必须全部满足：

- [ ] 机器狗前后左右至少留出 1.5 m 空间；
- [ ] 现场无人站在运动方向上；
- [ ] 遥控器零速度请求流已经停止；
- [ ] Jetson 上没有残留 Nav2、Web 控制或其他 `cmd_vel` 发布者；
- [ ] 使用独立闭环测试程序，不接入正式 `/cmd_vel`；
- [ ] 不发送 StandUp、BalanceStand 或其他隐式姿态动作；
- [ ] 速度不超过 `0.30 m/s`，目标距离不超过 `0.40 m`；
- [ ] 状态超过 0.15 秒未更新时立即 StopMove；
- [ ] 出现外部 Sport 请求、反向移动或过大横向偏移时立即 StopMove；
- [ ] 运动硬超时不超过 1.80 秒；
- [ ] 现场人员准备好物理断电手段；
- [ ] 测试完成后重新检查所有控制进程已退出。

测试结束必须由现场人员回答“移动/未移动、方向、距离、停止是否及时”。在得到该
反馈前，记录状态只能是 `PENDING`。

仅在上述条件全部满足并再次获得现场明确授权后，才可以运行：

```bash
cd /home/nvidia/Go2_Nav_ws
export UNITREE_INTERFACE=eth0
source /home/nvidia/unitree_ros2/setup.sh
source install/setup.bash

python3 scripts/go2/go2_closed_loop_motion_test.py \
  --armed YES \
  --speed 0.30 \
  --target 0.40 \
  --stop-trigger 0.38 \
  --max-motion 1.80 \
  --publish-rate 50
```

`--armed YES` 只是防止误运行的技术门槛，不能代替现场人员的当次授权。
