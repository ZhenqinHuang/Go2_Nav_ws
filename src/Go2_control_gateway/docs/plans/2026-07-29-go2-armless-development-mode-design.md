# Go2 无 Arm 开发模式设计

日期：2026-07-29
状态：已确认

## 1. 目标

在当前开发阶段，完全删除外载控制链路中的 Arm/Disarm 业务流程，减少人为操作和状态机握手造成的故障点。控制路径保持为：

```text
外载 Jetson Nav2 /cmd_vel
        ↓ ROS 2
外载 go2_cmd_vel_udp_sender
        ↓ UDP（CRC、序号、ACK）
内载 go2_cmd_gateway
        ↓ Unitree 原生 SportClient
Go2 下位机 192.168.123.161
```

“删除 Arm”只表示不再需要 Arm 按钮、Arm 服务、Arm token 或 Arming/Armed 状态才能发送速度。它不删除停止和故障保护。

## 2. 保留的安全边界

- 外载启动后默认发送零速度。
- Nav2 未活跃时才允许 Web 手动控制；Nav2 活跃时必须先取消导航。
- 手动速度命令和 Nav2 速度命令分别带有超时，超时后外载自动回零。
- UDP 帧保留版本、序号、CRC、源 IP 校验和 ACK。
- 内载只接受预期外载 IP 的数据。
- 内载 0.5 秒未收到有效控制帧时调用 `StopMove()`。
- 收到显式零速度时调用 `StopMove()`。
- SDK 异常、序号异常、CRC 异常或链路断开时不继续保持运动指令。
- Web 保留“停止”操作；停止不依赖 Arm/Disarm。

## 3. 协议兼容策略

为避免同时升级时出现包结构不一致，UDP 二进制包的旧 `arm_token` 和 flags 字段暂不改变布局：

- 外载固定发送 `arm_token = 0`。
- 正常速度帧固定发送 `flags = NONE`。
- 内载仅按无 Arm 速度帧处理，不再执行 `ARM_REQUEST`。
- ACK 继续使用既有包结构；状态字段作为协议兼容值，不再代表操作员 Arm 状态。

这意味着协议在字节层面向后兼容，但 Arm 功能在业务层面已经删除。

## 4. 外载行为

### 4.1 速度选择

外载 sender 不再以 `armed` 为发送速度的前置条件：

1. 启动时速度为零。
2. Nav2 活跃且 `/cmd_vel` 新鲜时选择 Nav2 速度。
3. Nav2 未活跃、Web 持有控制租约且手动速度新鲜时选择手动速度。
4. 其他情况发送零速度。

### 4.2 状态和接口

- 删除 Arm/Disarm 请求队列和 token 生成。
- 删除 ROS 2 Arm 服务和 Web `/api/arm`、`/api/disarm` 操作。
- Web 状态不再用 `armed` 决定控制按钮是否可用。
- 控制是否可用由网关在线、控制租约和 Nav2 状态共同决定。

## 5. 内载行为

### 5.1 无 Arm 网关

内载收到合法、顺序正确的 token 0 普通速度帧后直接进入速度处理：

- 非零速度：交给异步 SportClient worker。
- 零速度：调用 `StopMove()` 并清除运动目标。
- 不再经过 `Locked → Arming → Armed` 握手。

### 5.2 首次运动准备

Unitree 原生 SDK 的 `BalanceStand()` 仍是实际运动准备动作，但不再暴露成 Arm 状态：

- 进程启动后的首个非零速度到来时，SDK worker 在后台执行一次 `BalanceStand()`。
- `BalanceStand()` 成功后，worker 使用最新速度调用 `Move(vx, vy, vyaw)`。
- 准备过程不阻塞 UDP 接收和 ACK。
- 同一网关进程内停止后再次运动不重复执行 `BalanceStand()`。
- SDK 准备或 Move 失败时记录错误并进入停止状态。

## 6. Web 控制台

- 删除 Arm 状态卡、Arm 按钮和 Disarm 按钮。
- 手动控制条件改为：网关在线、已取得控制租约、Nav2 未活跃。
- 页面加载和 sender 启动时均保持零速度。
- 停止按钮继续发送零速度。
- 状态面板继续显示网关连接、Nav2 状态、当前速度、里程计和机器人基础状态。

## 7. 冒烟测试

测试脚本不再执行 Arm/Disarm：

1. 等待第一条网关状态和新鲜 ACK。
2. 确认网关在线、Nav2 未活跃。
3. 在用户单独确认真机测试后发送限定时长的低速命令。
4. `finally` 中连续发送零速度。

部署阶段只运行零速度和状态检查，不自动运行运动冒烟测试。

## 8. 验证顺序

1. 单元测试验证 sender 无 Arm 即可选取速度。
2. C++ 单元测试验证 token 0 普通帧可直接驱动、零速度停止、0.5 秒看门狗停止。
3. SDK pump 单元测试验证首次 `BalanceStand()` 异步执行且只执行一次。
4. Web 测试验证界面和 API 中不再存在 Arm/Disarm。
5. 构建外载 ROS 2 workspace 和内载网关。
6. 部署后只发送零速度，确认 ACK、序号、网关在线和看门狗状态。
7. 真机运动测试前明确告知用户测试距离、速度和预计时长，等待新的确认。
