# Go2 外载—内载控制链路文档设计

日期：2026-07-29

## 目标

把当前已经实现的“外载 Jetson NX → 内载 Ubuntu 板卡 → Unitree Go2 下位机”控制链路整理成两份可长期维护的 Markdown 文档：

1. 架构与接口说明：解释系统为什么这样连接、数据如何流动、每个进程和接口负责什么。
2. 部署与联调 Runbook：给出从零部署、上电检查、启动、调用、验收、停机和排障的可复制步骤。

读者不需要预先熟悉当前代码仓库。只阅读这两份文档，应能定位所有相关源文件，理解安全状态机，并在满足现场安全条件后打通链路。

## 交付结构

### 文档一：架构与接口说明

文件：`docs/Jetson_NX到Go2_控制链路架构与接口.md`

内容：

- 设备、网线、网卡、IP、端口和职责；
- 正向控制数据流与反向状态流；
- Nav2、Web、ROS 2、UDP、C++ 网关和 Unitree SDK 的边界；
- ROS 话题、服务、Action、HTTP API、WebSocket 接口；
- 56 字节控制帧和 ACK 的字段、字节序、校验规则；
- 外载与内载 fail-closed 状态机；
- `BalanceStand`、`Move`、`StopMove` 的调用位置；
- 新增代码文件清单及每个文件的职责；
- 当前已验证事实、未验证边界和安全限制。

### 文档二：部署与联调 Runbook

文件：`docs/Jetson_NX到Go2_控制链路部署联调日志.md`

内容：

- 从零安装外载和内载网关；
- NetworkManager 持久 IP 配置与路由检查；
- 构建、安装和 systemd 服务操作；
- 启动 MID360、定位、Nav2、UDP sender 和 Web 控制台；
- Web、ROS CLI、Nav2 Action 和 HTTP API 调用示例；
- 无运动测试、低速手动测试、Nav2 全链路测试；
- 预期输出、判定标准、故障树、恢复与回退；
- 按日期记录的已完成检查和待现场验收清单。

## 编写原则

- 以仓库当前源码和已部署配置为事实来源，不用假设补齐未知状态。
- 明确区分 2026-07-28 已验证结果、dry-run 结果和内载重新上电后的待验证结果。
- 所有可能导致运动的命令都标注前置安全条件，并紧邻给出归零或 Disarm 命令。
- 不在 GitHub 文档中保存明文密码、哈希、Cookie、Arm token 或 SSH 私钥。
- 保留已经测试通过的 MID360、建图、定位和 Nav2 链路；新增文档只解释速度执行链路如何接入。
- 旧的外载直连 DDS bridge 仅作为诊断回退，不描述为正常运行路径。

## 验证方法

- 对照源码逐项核对 IP、端口、话题、服务、Action、API 路径、状态枚举和超时参数。
- 检查文档引用的文件在仓库中存在。
- 检查所有代码块闭合、内部链接有效、文档中不包含已知明文凭据。
- 运行现有 Python 和前端测试，确认仅新增文档未改变运行代码。
