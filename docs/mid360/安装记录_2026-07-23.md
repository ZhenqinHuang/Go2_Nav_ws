## 4. 遇到的问题及处理

### 4.1 参考文档与 Jetson ROS 版本不一致

- 现象：参考资料部分命令针对 Ubuntu 22.04 / ROS 2 Humble，本机为 Ubuntu 20.04 /
  ROS 2 Foxy。
- 原因：ROS API 与二进制包版本存在差异，不能直接照搬。
- 处理：以实际 Jetson 环境为约束，使用 Ericsii 的 ROS 2 分支并固定全部源码提交；
  安装脚本增加系统、架构和 ROS 文件检查。
- 验证：三个固定版本均检出成功，SDK、驱动和 FAST-LIO 均完成构建。

### 4.2 FAST_LIO_ROS2 在 Foxy 编译失败

- 现象：`laserMapping.cpp` 的地图保存服务回调使用
  `std_srvs::srv::Trigger::Request::ConstSharedPtr`，Foxy 的
  `rclcpp::AnyServiceCallback` 无法匹配。
- 根因：该分支面向较新的 ROS 2 API；Foxy 需要可变的
  `Request::SharedPtr`。
- 证据：原始固定提交在同一处稳定复现编译错误；检查本机 Foxy 头文件后确认签名限制。
- 修复：保存最小补丁
  `scripts/mid360/patches/fast_lio_ros2_foxy_service_callback.patch`，只修改该请求参数类型。
- 回归测试：先用
  `scripts/mid360/tests/test_fast_lio_foxy_compat.sh` 在原始代码上得到失败，再应用补丁
  得到通过。
- 验证：补丁后 `fast_lio` 构建完成，节点限时启动并输出 `Node init finished`。

### 4.3 无雷达时 Livox 驱动 bind failed

- 现象：雷达未接入时，NetworkManager 保存了静态配置，但 `eth0` 无 carrier，
  `192.168.1.5` 未成为活动地址，驱动绑定主机地址失败。
- 根因：这是无物理链路时的网络状态，不是 JSON 解析或驱动编译失败。
- 处理：仅在一次受控烟雾测试中临时给 `eth0` 添加 `192.168.1.5/24`，退出时用 trap
  删除，没有改默认路由。
- 验证：临时地址存在时驱动成功解析配置并输出 `Init lds lidar success!`；限时结束后
  地址已清理。
- 剩余限制：真实 UDP 点云只能在雷达接入后验证。

### 4.4 首次临时烟雾测试被未定义变量中断

- 现象：测试 shell 使用 `set -u`，ROS Foxy 的 setup 脚本读取尚未定义的
  `AMENT_TRACE_SETUP_FILES`，节点启动前退出。
- 根因：Foxy 环境脚本与 nounset 模式不兼容。
- 处理：加载 ROS setup 时短暂 `set +u`，之后恢复 `set -u`。安装与验证脚本都使用
  同一防护方式。
- 验证：再次执行时 Livox 和 FAST-LIO 烟雾测试均能进入节点启动阶段。

### 4.5 最小补丁缺少上下文时反向检查失败

- 现象：只保留单行变更的 patch 可以人工看出一致，但
  `git apply --reverse --check` 不能识别已应用状态。
- 原因：上下文不足，补丁定位不稳定。
- 处理：保留下一行函数体 `{` 作为上下文。
- 验证：正向和反向检查均正常，安装脚本可重复识别补丁状态。

### 4.6 非阻塞构建警告

- livox_ros_driver2 的 PCAP、PNG、libusb 可选功能未启用；MID360 原始 UDP/ROS 发布
  不依赖这些功能。
- FAST-LIO 构建出现 PCL 旧类型弃用警告，但编译成功。
- Go2 工作区已有 `Go2_web_bridge` 包命名风格警告，未导致构建或测试失败。
